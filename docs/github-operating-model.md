# GitHub operating model

## Assigning work

Create one issue per session using the `System design lesson` template. Assign it to the learner, add the session label, and put it on the Project board. A study partner can be assigned as reviewer rather than implementer.

## Pull requests

One pull request should contain one learning outcome. It may include code, tests, a diagram, and evidence, but it must not mix unrelated sessions. Link the issue with `Closes #123` only when all acceptance criteria are complete.

## Wiki and Discussions

- **Wiki:** durable explanations, diagrams, and session guides.
- **Discussions:** spoken interview answers, design alternatives, and questions.
- **README:** entry point, schedule, and links.
- **Issues:** assignments and acceptance criteria.
- **Project:** progress tracking.

## Definition of done

- The learner can explain the concept without notes.
- The listed example code paths were inspected, or a local example was created.
- The code lab or evidence artifact is committed.
- The AWS/Google Cloud/GitHub platform mapping is documented.
- Tests or validation run successfully.
- No credentials, tokens, or personal data are included.
- A reviewer has checked the trade-off and failure mode.
